# BigQuery Sales Data Warehouse

A small data warehouse on Google BigQuery. It loads e-commerce order data through Google Cloud Storage, models it as a **star schema**, and answers business questions with SQL (CTEs and window functions). A Looker Studio dashboard can be built on top.

## Architecture

```
generate_data.py  ->  orders.csv  ->  Cloud Storage  ->  BigQuery stg_orders (staging)
                                                              |
                                                              v
                                    dim_customer  dim_product  dim_location  dim_date
                                                              |
                                                       fact_sales
                                          (partitioned by order_date,
                                           clustered by region, category, customer_id)
                                                              |
                                                              v
                                         sql/03_analytics.sql  ->  Looker Studio
```

## Data

The dataset is **synthetic**, generated by `generate_data.py` (50,000 orders across 2024-2025, 4 regions, 4 categories, 3 sales channels). A fixed random seed makes it reproducible. You can also point the loader at a public dataset (for example the Olist or Superstore dataset from Kaggle) if you map its columns to the staging schema in `sql/01_staging.sql`.

## Data model (star schema)

| Table | Type | Notes |
|-------|------|-------|
| `fact_sales` | Fact | One row per order; `net_revenue` = quantity x unit_price x (1 - discount). Partitioned by `order_date`, clustered by `region, category, customer_id`. |
| `dim_customer` | Dimension | customer_id, name, segment |
| `dim_product` | Dimension | product_id, name, category, list price |
| `dim_location` | Dimension | region, city |
| `dim_date` | Dimension | year, quarter, month, weekday, weekend flag |

Partitioning by date limits how much data a time-filtered query scans, and clustering speeds up filters and joins on the clustered columns. Both reduce query cost.

## Analytical queries (`sql/03_analytics.sql`)

1. Monthly revenue with month-over-month growth (`LAG`)
2. Top 3 products per category (`RANK ... PARTITION BY`)
3. Top 10 customers by lifetime value with cumulative revenue share (running `SUM` window)
4. Revenue share by channel within each region (`SUM ... OVER (PARTITION BY ...)`)

## How to run

### 1. Local check (no GCP needed)

```bash
python generate_data.py --rows 50000 --out data/orders.csv
python local_validate.py --csv data/orders.csv
```

This runs data-quality checks (no duplicate order IDs, no null keys, positive revenue) and the four analytical queries on SQLite using only the Python standard library.

### 2. On Google Cloud

```bash
pip install -r requirements.txt
gcloud auth application-default login
export GCP_PROJECT=your-project-id
export GCS_BUCKET=your-bucket-name       # must already exist
export BQ_DATASET=sales_dw               # optional
python load_to_bigquery.py --csv data/orders.csv
```

Then open `sql/03_analytics.sql` in the BigQuery console (replace table names with `your-project.sales_dw.fact_sales`) and run the queries.

### 3. Dashboard

In Looker Studio, add BigQuery as a data source, select `fact_sales`, and build charts for monthly revenue, revenue by region and channel, and top products. Add a screenshot to this README under a "Dashboard" heading.

## Project structure

```
generate_data.py        synthetic data generator
load_to_bigquery.py     GCS upload, BigQuery load, star schema build
local_validate.py       local data checks and query test (SQLite)
sql/01_staging.sql      dataset and staging table
sql/02_star_schema.sql  dimensions and partitioned/clustered fact table
sql/03_analytics.sql    analytical queries
```

BigQuery, Cloud Storage, SQL, Python (google-cloud-bigquery, google-cloud-storage), Looker Studio

## Testing status

- Data generation and the data checks and analytical query logic were run locally (`local_validate.py`).
- The BigQuery loader and DDL (`load_to_bigquery.py`, `sql/01` and `sql/02`) are written for BigQuery but were not run against a live project by the author of this template. Run them in your own GCP project (the free tier is enough) and fix any project-specific details before relying on them.
